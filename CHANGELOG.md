# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.5.0] - 2026-08-13

Two new engine capabilities closing real, code-grounded gaps identified from a review of every content-generation use case clearfelt was being asked to cover, plus a full push to literal 100% line/branch/function test coverage across the repo.

### Added

- **Personal calibration.** New `scripts/calibrate.mjs` computes a writer's own MATTR (vocabulary diversity), sentence-length burstiness, and paragraph-length variance from a writing sample or a directory of past drafts, reusing the same statistical functions `scripts/lib/score.mjs` already exports rather than adding new statistical code. `/clearfelt setup` runs it automatically and stores the result in `.clearfelt/voice-profile.md`'s new "Personal calibration (computed)" section; `scripts/lib/config.mjs`'s new `loadVoiceProfileCalibration()` reads it back and overrides `clearfelt.config.md`'s generic, fixture-derived `vocabulary_diversity_baseline`, `burstiness_baseline`, and `paragraph_variety_baseline` for that project's scoring only. Strictly additive: a project that never runs it sees identical behavior to before. See `reference/setup.md`.
- **Hard, checkable constraints.** New `--max-chars`, `--max-words`, `--must-contain`, and `--must-not-contain` flags on `/clearfelt rewrite` and `/clearfelt write`, usable inline for a one-off limit or as a reusable named set at `.clearfelt/constraints/<name>.md` (new `templates/constraints.example.md`), passed with `--constraints <name>`. `scripts/check.mjs` verifies every declared constraint against the actual candidate text after a scrub or draft pass, not a prompt-only instruction: a length overshoot hard-fails by default, `must_contain`/`must_not_contain` follow the same `check.hard_fail_on_constraint_violation` toggle pattern already used for dropped/added facts. `prompts/write_loop.xml` and `prompts/audit_loop.xml` pass an active constraint set into every scrub pass, the same way locked spans already are, so generation targets it directly instead of only being checked afterward. New `docs/ROADMAP.md` documents two related features considered and deliberately not built this cycle (a structural-variety check against a corpus, and platform-scoped non-negotiables within one voice profile), with the reasoning for each.

### Fixed

- **`scripts/check.mjs`'s blockquote-preservation check was permanently dead code.** `extractQuotes`' blockquote detection was always run on `stripExcludedRegions()`-stripped text, the same text passed to the other three fact extractors, but stripping blanks out blockquote lines specifically, so a dropped or added blockquote could never be detected. Fixed by extracting quotes from the untouched raw text instead, keeping the other three extractors on the stripped text as before.
- **Two real test-suite concurrency bugs**, both found while pushing test coverage: `node --test` runs separate test files concurrently by default, and multiple test files independently backing up, mutating, and restoring the same real shared files (`~/.clearfelt/settings.md`, `tests/fixtures/.clearfelt/`) raced on which process's "did this exist before" check ran when, occasionally corrupting the other file's restored state. Fixed with a new `tests/helpers/global-settings.mjs`, a cross-process lock (atomic directory creation) shared by every test file that touches either path.

### Changed

- **Line, branch, and function test coverage is now literal 100%** (`node --test --experimental-test-coverage`) across every script and library file in the repo, up from roughly 75% branch / 92% function at the start of this cycle. Closed by writing a real, honest test for every legitimately reachable branch (including several requiring new dependency-injection seams, like `scripts/hook.mjs`'s `runHookBody` now taking optional `readStdin`/`runDetect`/`state` parameters so its stdin-failure and malformed-output paths can be exercised directly) and by simplifying away a handful of defensive branches proven unreachable given the codebase's own invariants (a `mean === 0` guard in `burstinessScore`/`paragraphStructureScore` where `lengths` is always pre-filtered to positive values; a `trigrams.length === 0` guard already covered by an earlier `words.length < 3` check; a `contextFor` not-found branch where the search value always originates as a literal substring of the text being searched), each left with a comment explaining why the branch could never trigger rather than a contrived test forcing it to.

## [0.4.0] - 2026-08-13

Found entirely through dogfooding `/clearfelt setup`, `/clearfelt audit`, and `/clearfelt explain` against a real test project after v0.3.0 shipped, plus a structured three-persona review (prose self-consistency, software engineering, agent-pipeline design) of the whole repo.

### Added (`/clearfelt write`)

- **New `/clearfelt write [seed]` command**, turning a short seed (a rough draft, a paragraph of notes, an idea pasted straight into the request) into a full first draft, instead of editing an already-substantial document the way `/clearfelt rewrite` does. Driven by a new `prompts/write_loop.xml` (seed and interview, draft from seed, score and preserve), which reuses `/clearfelt rewrite`'s scoring, preservation-checking, confirm-before-write gate, and voice-profile precedence rather than duplicating any of it, the only new logic is the interview, the draft-generation pass, and a narrowed no-fabrication check (against the seed and interview answers, since there's no source document). A short interview (at most 4 questions, same `AskUserQuestion` wizard pattern as `/clearfelt setup`) resolves anything the seed doesn't already state. Length (`short`/`medium`/`long`) replaces intensity as write's one tuning axis, since there's nothing existing to decide how much of to touch; resolved the same way, `.clearfelt/domain.md`'s new `preferred_length` field, then a saved global preference, then ask. Always writes to a new file, never overwrites the seed. New `reference/write.md`, new `## Write` section in `clearfelt.config.md` (`length`, `write.ask_length`), new "Preferred length" section in `templates/domain.example.md`, new `/clearfelt write` templates in `reference/output-format.md`, `scripts/explain.mjs` and its output template gained `preferredLength`. `scripts/pin.mjs`'s `VALID_COMMANDS` gained `write`.

### Added (`/clearfelt setup`)

- **`/clearfelt setup` now detects a project's own pre-existing voice or style document** (`voice.md`, `VOICE.md`, `docs/voice.md`, `docs/VOICE.md`, `STYLE.md`, `docs/STYLE.md`, or a path the user supplies directly if none of those match) and asks explicitly whether to keep it as the voice source or build a fresh profile from the usual interview, rather than silently ignoring it or overwriting it. If kept, only asks about whichever of the four working fields (words to keep, words to avoid, sentence rhythm, non-negotiables) the source file doesn't already cover, purely additive to what the file already says, never restating or overriding it. `.clearfelt/voice-profile.md` opens with an explicit source note pointing back at the original file, since `scripts/lib/config.mjs`'s override lookup only ever reads `.clearfelt/voice-profile.md` directly and does not follow a reference at runtime. The original file is only ever read, never written to, under any circumstance. See `reference/setup.md`.

### Fixed

- **A labeled fixture set and a real consistency measurement for the "qualitative signals" reasoning step** (`reference/audit.md`'s narrative idiosyncrasy, episodic grounding, cognitive friction, synonym cycling, admits real stakes), the one part of the scoring pipeline that previously had zero eval coverage. New `tests/fixtures/qualitative/` (4 fixtures) and `scripts/qualitative-eval.mjs`, which scores recorded judgment runs and reports pairwise agreement between them once two or more exist. Seeded with two real runs: 90% pairwise agreement, the one disagreement landing on synonym cycling, exactly the signal `reference/audit.md`'s own text already calls "the harder case."
- **Nine issues found by a three-persona review** (prose self-consistency, software engineering, agent-pipeline design), the most notable being `scripts/lib/config.mjs`'s `CONFIG_DEFAULTS` holding stale, pre-`docs/decisions/0011` scoring weights that would have silently overridden `score.mjs`'s own correct fallbacks had a shipped config row ever gone missing, and the eval corpus (16 fixtures, one disclosed miss) growing to 28 across three new genre buckets (`marketing`, `technical`, `personal`) after investigating that miss surfaced two real rule-dictionary gaps rather than a threshold problem. New `scripts/lint.mjs` checks (`checkConfigDefaultsDrift`, `checkOutputShape`) and a new `tests/hook.test.mjs` (12 tests) guard against the same classes of bug recurring. Full list: `docs/decisions/0018-multi-persona-review-fixes.md`.
- **Vocabulary diversity could single-handedly cancel out a capped rule-hit deduction on a long document.** An 841-word AI-generated document with 27 rule hits (the highest hit count tested) scored 99/100, "reads clean," because Root TTR (`docs/decisions/0012`) still grows with document length past the 16-fixture corpus it was calibrated against (15.45 measured, versus a 5.7-7.4 calibrated band) and its +69.98 bonus outweighed the -65 capped deduction. Replaced with MATTR (Moving-Average Type-Token Ratio, windowed, length-invariant by construction), recalibrated `vocabulary_diversity_baseline`/`vocabulary_diversity_weight`. The same document now scores 31/100, correctly led by its rule-hit deduction. `scripts/eval.mjs` pass rate unchanged at 15/16. See `docs/decisions/0017-windowed-vocabulary-diversity.md`.
- **`scripts/explain.mjs` couldn't parse a real `.clearfelt/domain.md`'s `mode` field**, and didn't recognize the template's own `(unset)` sentinel for `preferred_intensity` as meaning "not set." Found running `/clearfelt explain` against a freshly-written domain profile. Both fixed.

### Changed

- **`/clearfelt setup`'s interview now runs entirely through the harness's structured single-choice question tool**, one question per turn, never a plain conversational text prompt, including open-ended questions (a writing sample, preferred words), which get 2-3 concrete example options plus the tool's own free-text "Other" slot rather than an open prompt. See `reference/setup.md`'s new wizard rule.
- **`/clearfelt audit` and `/clearfelt rewrite`'s output redesigned for readability**, prompted by two persona reviews (a product read, then a data-presentation read) of a real audit response: a plain-English verdict (Reads clean / Borderline / Needs work) now leads every response, before any table; every table gets a one-sentence lede explaining what it shows and how it relates to the section above; a new required "Directory audit summary" template names every file explicitly and ranks worst-first when auditing more than one file, instead of leaving the reader to infer scope; the "Where"/patterns table now shows the already-computed `points` value it's sorted by, instead of asking the reader to multiply severity by occurrences themselves; readability metrics get a plain-language band (e.g. "post-graduate reading level") alongside the raw number; all human-facing impact values are rounded to whole points, raw precision stays in the JSON. See `reference/output-format.md`.

## [0.3.0] - 2026-08-13

All five phases of the v0.3 plan (bug fixes, eval recall gap, doctrine files, v2 scoring/rewrite architecture, CI), reconciling a code-grounded architecture audit and a product-brainstorm spec doc against the actual repo before implementing either, plus a second round closing six findings from a multi-persona critique of the shipped skill.

### Breaking

- **`/clearfelt humanize` renamed to `/clearfelt rewrite`.** The command's whole reference file moved (`reference/humanize.md` to `reference/rewrite.md`), and its config keys were renamed to match: `empathy_threshold` to `human_score_threshold`, `humanize.require_confirmation` to `rewrite.require_confirmation`, `humanize.ask_intensity` to `rewrite.ask_intensity`. No migration shim: an existing `~/.clearfelt/settings.md` or `.clearfelt/domain.md` using the old key names will silently stop applying until updated to the new names. The "Empathy Index" score name is retired in favor of "Human Score" (the JSON field itself was already just `score`, unaffected). `writing.md` and `voice.md` still describe the same doctrine; only the command/setting names and score label changed. `docs/decisions/0001` through `0015` and every already-released changelog entry below keep the old names, they're an accurate historical record of what was decided under them at the time, not updated.

### Added (preservation checker)

- **`scripts/check.mjs`**, a new dependency-free script that deterministically diffs a rewrite candidate against its source: every `<!-- clearfelt-lock -->` span is checked for byte-identical content (always blocks the write on a mismatch), and a regex-based fingerprint of numbers, dates, proper nouns, and quoted material is compared before and after (warns by default, configurable to block via new `check.hard_fail_on_dropped_fact`/`check.hard_fail_on_added_fact` settings). Closes the gap where no-fabrication and locked-span guarantees were previously enforced only by prompt instruction, never verified in code. Wired into `prompts/audit_loop.xml`'s Pass 3, alongside the existing threshold check. New `## Preservation checking` section in `clearfelt.config.md`; new "Preservation check" subsection in `reference/output-format.md`'s rewrite template. See `docs/decisions/0016-preservation-checker.md` for the heuristic tradeoffs disclosed per extractor, and `tests/check.test.mjs`.

### Added (`/clearfelt explain`)

- **New `/clearfelt explain` command**, read-only, printing every currently-resolved config setting with its provenance (default, shipped `clearfelt.config.md`, or global `~/.clearfelt/settings.md`), plus active voice-profile and domain-profile state and hook status, all in one place before running anything else. `scripts/explain.mjs`; `scripts/lib/config.mjs` gained `loadConfigWithProvenance()`. `reference/explain.md`; `scripts/pin.mjs`'s `VALID_COMMANDS` gained `explain`.

### Changed (architecture)

- **`scripts/detect.mjs` (829 lines) split into `scripts/lib/`**: `config.mjs` (config precedence, voice/domain overrides), `rules.mjs` (rule-dictionary parsing and matching), `score.mjs` (statistical signals, readability, the score formula), `report.mjs` (summaries and the single-file orchestration). `detect.mjs` is now a thin CLI entrypoint importing from these; CLI output is unchanged (`tests/detect.test.mjs`, `scripts/eval.mjs`, and `scripts/hook.mjs` all invoke it as a subprocess and needed no changes). `scripts/lint.mjs`'s `checkConfigDrift()` updated to scan every `.mjs` file under `scripts/`, not just `detect.mjs` and `hook.mjs` by name, so the split doesn't produce a false-positive config-drift failure.
- **`scripts/hook.mjs`'s `readState()` exported**, and its `main()` call guarded so importing the module (used by `scripts/explain.mjs`) no longer triggers the PostToolUse hook body or an admin action as a side effect.

### Fixed

- **`scripts/pin.mjs` could silently overwrite an unrelated skill.** `pin()` now checks for a pre-existing `SKILL.md` at the target path before writing, mirroring `unpin()`'s existing marker check: if one exists and lacks the `<!-- clearfelt-pinned-skill -->` marker, that harness directory is skipped with a message rather than clobbered. A conflict in one harness directory no longer blocks pinning into the others. New `tests/pin.test.mjs`.

### Added (schemas and reports)

- **`schemas/rule-bullet.schema.json`, `schemas/eval-manifest.schema.json`**: document the previously prose-only rule-bullet and eval-manifest shapes, primarily for editor autocomplete (`manifest.json` now carries a `"$schema"` field) and as a single source of truth for `scripts/lint.mjs`'s checks, not a generic JSON-Schema validation engine (this repo stays dependency-free). New `checkRuleBulletShape()` lint check catches an empty pattern or a severity/tier outside the documented range, previously silent.
- **`reports/`**, a new gitignored, opt-in directory for durable artifacts, never a default write target: `/clearfelt audit` can save a rendered report there on request; `scripts/eval.mjs` gained an optional `--out <file>` flag to write its pass/fail summary as JSON for trend comparison across releases; `scripts/check.mjs` logs a hard-fail verdict there automatically for later review.

### Added (Phase 5: automated checks)

- **`scripts/lint.mjs`**, zero dependencies, same rule as `detect.mjs`: `SKILL.md` frontmatter (required fields, non-standard fields as a warning, catching the still-open `version` field from the original architecture audit), `prompts/audit_loop.xml` tag balance, every rule's `source:` key resolving to a real `docs/SOURCES.md` row, every `clearfelt.config.md` row actually being read in `scripts/`, and the em-dash prohibition across the whole repo. The config-to-code drift check is verified against its own target bug shape: an injected orphan config section is caught and reported before being reverted.
- **`.github/workflows/ci.yml`**, running `node --test`, `node scripts/lint.mjs`, and `node scripts/eval.mjs` on every push and PR. `eval.mjs` stays non-gating by design, a low pass rate is a disclosed finding to act on deliberately (docs/decisions/0010, 0012), not a CI failure; `--test` and `lint.mjs` do gate.
- `docs/DEVELOP.md` and `docs/RELEASE.md` updated to make `lint.mjs` the standard pre-PR and pre-release check, alongside `node --test` and `node scripts/eval.mjs`.

### Added (Phase 4: v2 scoring and rewrite architecture)

- **`mode` field in `.clearfelt/domain.md`** (technical, marketing, support, executive, personal, sensitive), extending the existing domain-profile mechanism instead of building a parallel mode system. Informational context for `/clearfelt humanize`'s qualitative judgment calls, not a new enforcement switch: does not change what `scripts/detect.mjs` flags or scores. `risk_tier: sensitive` (unchanged) remains the actual enforcement mechanism for sensitive content; setting `mode: sensitive` alone does not grant its protections.
- **Intensity-ladder terminology reconciled** in `reference/humanize.md`: a note mapping the existing four tiers (`light_touch`/`balanced`/`full_rewrite`/`structural_rework`) onto the spec doc's no-touch/minimal-touch/transform/aggressive language, so the two namings are understood as one system, not built as two.
- **`rules/banned_words/confidence_inflation_lexicon.md`**, a new rule category (7 phrases: "impossible to overstate," "guaranteed to," "the ultimate solution," and similar), the one genuinely new scoring dimension from the spec doc's multi-dimensional-scoring request that shipped. Fits the existing category mechanism exactly: no change needed to `computeScore`, `categoryPoints`, or `impacts`, all three already handle a new category file automatically.
- `docs/decisions/0014-multi-dimensional-scoring-scope.md`, documenting what shipped and what didn't: cliché density was already covered by `categoryPoints`; a candidate specificity signal was measured against all 16 eval fixtures and rejected for being noisy and inconsistent at these document lengths (higher on an AI fixture than every human fixture); clarity was rejected outright as a scoring dimension, not deferred, since it would reverse `docs/decisions/0008`'s deliberate decision to keep readability separate from the Empathy Index.
- **Explainable diffs.** `/clearfelt humanize`'s "Changes made" section now attributes every changed span to the `patternSummary` pattern/category or `breakdown.impacts` label that actually drove it, and now also lists spans that matched a rule but were deliberately left alone (risk-tier protection, a domain exemption, a voice-profile preference, or a locked span) instead of only reporting what moved. See `reference/output-format.md`.
- **Locked spans.** `<!-- clearfelt-lock -->` / `<!-- /clearfelt-lock -->` marker pairs, placed directly in a target document, protect the wrapped text from `/clearfelt humanize` at every intensity tier, a narrower, per-span alternative to declaring a whole project `risk_tier: sensitive`. Scoring is unaffected: a rule hit inside a locked span still counts in `/clearfelt audit`'s report exactly as it would anywhere else. See `reference/humanize.md`'s "Locked spans" and `docs/decisions/0015-locked-spans.md`. Implemented entirely in `prompts/audit_loop.xml`, `scripts/detect.mjs` is unchanged, since humanize's rewriting is LLM-driven by design (`docs/decisions/0001`), not something the scoring script does.

### Added (Phase 3: doctrine)

- **`writing.md`**, root-level editorial doctrine: what clearfelt considers bad writing, what it always preserves, refusal rules, and the underlying principle every rule and rewrite instruction should be an implementation of. Referenced directly from `SKILL.md` and `prompts/audit_loop.xml`'s Pass 1 and Pass 2, not left as background reading.
- **`voice.md`**, root-level doctrine about the voice-profile *system* (precedence, what it will and won't override), not a data file. `.clearfelt/voice-profile.md` (or `.clearfelt/voices/<name>.md`) remains the actual per-project data, unchanged.
- `docs/decisions/0013-writing-and-voice-doctrine.md`, including why `product.md`/`design.md` were considered and rejected: those names are already owned by the separate `impeccable` skill (`/impeccable init` generates exactly those two files), confirmed by reading its documentation rather than assumed.

### Fixed

- **Directory scanning crashed with EISDIR.** `/clearfelt audit <directory>` and `node scripts/detect.mjs --mode report <directory>` now scan every `.md`/`.txt`/`.mdx` file in the directory and aggregate a combined report (`score` is the average across files, `files` lists each one), instead of throwing on `readFileSync` against a directory handle. `--mode score` on a directory returns `{ score, files }`.
- **Structural placeholder rule patterns never matched real text.** Bullets like `"It's not X. It's Y."` and `"colon-reveal: The best part: it learns."` in `rules/antipatterns/binary_contrasts.md` and `structural_tells.md` were matched as literal strings, capital X/Y, colon-reveal label prefix and all, so they could never fire on real prose. New `regex: true` bullet field (see `CONTRIBUTING.md`) opts a bullet out of literal-string escaping; the four binary_contrasts template patterns and the colon-reveal structural_tells pattern are now real regexes. `structural_tells.md`'s synonym-cycling bullet (comparing meaning across sentences, not pattern-matchable) moved to a new "Synonym cycling" note under `reference/audit.md`'s Qualitative signals, alongside `frictionless_claims.md`'s existing regex/reasoning-step split.
- **`tier2_cluster_window` was loaded from config but never used.** The tier-2 check was "does this same pattern appear more than once," not the documented "does another flagged word appear within `tier2_cluster_window` words." `findHits` now tracks each occurrence's global word position and checks proximity against every hit in the document, any rule, any category, matching the config's actual documented behavior. This alone moved `scripts/eval.mjs` from 5/10 to 7/10, since several AI-heavy fixtures' tier-2 words were being silently suppressed despite sitting in the same dense paragraph as other flagged words.
- **No path validation.** `detect.mjs`'s target path and `hook.mjs`'s PostToolUse `file_path` are now both required to resolve (symlinks included) inside the current project directory; a crafted path or payload pointing outside it is now rejected (`detect.mjs`, with an error) or silently skipped (`hook.mjs`, since it runs unattended after every edit).
- **Dead Hooks config rows.** `clearfelt.config.md`'s `## Hooks` section (`hook.enabled`, `hook.quiet`) was never read by `hook.mjs` or `detect.mjs`'s `loadConfig()`; hook state lives solely in `.clearfelt/hook-state.md`, as `reference/hooks.md` already correctly documented. The dead rows are removed and replaced with a pointer to the file that actually controls hook state.
- **Vocabulary-diversity scoring rewarded short documents for being short**, not for genuinely varied word choice, the regression ADR 0011 disclosed rather than hid. Switched from raw type-token ratio to length-normalized Root TTR (Guiraud's R, `guiraud-1954`); see `docs/decisions/0012-length-normalized-vocabulary-diversity.md`. New `vocabulary_diversity_baseline` config; `vocabulary_diversity_weight`'s default changed (17 to 8) since it now applies to a different scale. Raw TTR is still reported (`breakdown.typeTokenRatio`), just no longer score-affecting; `breakdown.rootTypeTokenRatio` is the new score-affecting value.

### Added

- `--mode scan` added to `detect.mjs --help`'s validated mode set; unknown `--mode` values now exit with an error instead of silently falling through to `report`.
- `--help`/`-h` flag on `detect.mjs`.
- Five lexicon entries: `pave the way`, `unwavering commitment`, `multi-faceted approach` (`rules/banned_words/puffery_lexicon.md`), `frictionless`, `rest assured` (`rules/antipatterns/frictionless_claims.md`), all `source: clearfelt-heuristic`, surfaced as genuine rule-dictionary coverage gaps while closing the eval recall gap. Combined with the fixes above, `scripts/eval.mjs` moved from 5/10 to 15/16 (see below for the one remaining, disclosed miss).
- `docs/decisions/0012-length-normalized-vocabulary-diversity.md`.
- `guiraud-1954` in `docs/SOURCES.md` (Root TTR / Guiraud's R; formula and attribution verified via a secondary source, the book itself has no free full text, same situation as `gunning-1952`).
- **Eval manifest grown from 10 to 16 fixtures**, adding three new self-labeled content buckets (`bucket` field, new): support replies, executive summaries, and sensitive/legal-flavored text. The sensitive bucket's human fixture (dense, hedged, legalese-adjacent) scores 92, confirming formality and precision aren't mistaken for AI slop on their own, one of the concerns raised in the product-brainstorm spec doc's critique pass. This is still a self-labeled set, not an independently-rated benchmark corpus; see `docs/decisions/0012` and the v0.3 plan's Phase 5 for why that stays out of scope for now.

### Known gap, disclosed rather than tuned away

- `ai-7.md` (executive-summary bucket, added this round) scores 75 against an expected 0-70 band, a genuine miss, not a bands issue: it's deliberately written as vague, hedge-free corporate boilerplate without any single glaring cliché, closer to how real executive summaries actually sound. Two rounds of lexicon additions closed similar misses in the support and sensitive buckets, but padding the dictionary further specifically to catch this one hand-authored fixture would be overfitting the rule set to a single test case rather than improving real recall, so it's left as an honest miss instead of a passing dictionary entry.

## [0.2.0] - 2026-08-13

Prompted by evaluating clearfelt as an editor at a tech magazine would: four scale/trust gaps addressed, plus a README repositioning to match. All additive and backward compatible; existing projects with no `.clearfelt/` files behave exactly as before.

### Added (this round: multi-persona critique converted to fixes)

- **Automated test suite.** `tests/detect.test.mjs` (Node's built-in test runner, `node --test`, no new dependency) runs `scripts/detect.mjs` as a real subprocess against fixtures in `tests/fixtures/`, including a regression test for the round-9 category-severity-weight bug. Prompted by an engineering audit finding zero tests anywhere in the repo for a tool whose entire claim is deterministic reproducibility.
- **A lightweight eval set.** `tests/fixtures/eval/` (10 labeled fixtures) plus `scripts/eval.mjs` reports how many land within their expected score band. Not full validation, an honest first check. Current result, kept rather than tuned away: 5/10, all five AI-heavy fixtures score higher than expected because short, single-occurrence slop words get suppressed by tier-2/tier-3 thresholds, a real, disclosed detection-recall gap.
- **`risk_tier` field in `.clearfelt/domain.md`.** `standard` (default) or `sensitive`. When `sensitive`, `/clearfelt humanize` never rewrites away hedges, qualifiers, or attributions (`frictionless_claims`, `weasel_attribution`), and the confirm-before-write gate is forced on regardless of other settings. See `docs/decisions/0010-risk-tier-and-test-suite.md`.
- **`.clearfelt/audit.log`.** `/clearfelt humanize` now appends a line (timestamp, path, intensity, score delta, approval) on every write, the first durable record of a humanize run; previously nothing survived past the terminal session that approved it.
- `docs/decisions/0010`: new ADR covering all of the above.

- **Output readability: sorted, grouped, and hierarchical instead of a flat unsorted dump.** Prompted by a readability critique of the output itself. `scripts/detect.mjs`'s report mode now returns `leadDriver` (one-line "what actually drove this score"), `breakdown.impacts` (every nonzero scoring factor, normalized to one consistent sign convention, sorted by magnitude), `categoryPoints` (severity-weighted point subtotal per category, sorted descending, not just a raw hit count that treats one severity-8 hit the same as one severity-1 hit), and `patternSummary` (repeated hits of the same pattern collapsed into one row with an occurrence count and line list, instead of one row per occurrence). `reference/output-format.md`'s `/clearfelt audit` and `/clearfelt humanize` templates rewritten to present these pre-sorted tables in order, rather than re-sorting or explaining the score in prose.
- **`deduction_cap` and a rescale of every statistical signal weight.** Measured across 17 real documents scored this session, rule-hit deduction (unbounded) spanned 0-86 while every statistical signal combined (bounded by its own formula) never exceeded about 5 points, meaning past roughly 2 rule hits the statistical signals were mathematically incapable of affecting the score at all. New `deduction_cap` setting (default 65) in `clearfelt.config.md` clamps deduction's effect on the score without hiding the raw number (`breakdown.deduction` stays the true sum; `breakdown.deductionApplied` is the capped value actually used; `breakdown.deductionCapped` flags the divergence, and the top `impacts` row's label discloses it directly, e.g. "capped from 119"). `burstiness_weight` (10 to 12), `vocabulary_diversity_weight` (5 to 17), `repetition_weight` (5 to 27), and `paragraph_variety_weight` (8 to 12) were rescaled using the observed-range data, not round-number guesses. See `docs/decisions/0011-deduction-cap-and-signal-rebalance.md`, including why a fourth option (rescaling everything to percentile bands against the eval corpus) was considered and explicitly deferred rather than folded in, the eval corpus is too small (10 fixtures) for percentile ranking to mean anything yet.
- **Release checklist now requires a README/doc sync, not just a version bump.** `docs/RELEASE.md`'s Steps gained an explicit step covering "Major features," the "Before and after" example scores (which are real, computed numbers and had drifted out of date after the deduction-cap rebalance above), the Usage table, the Architecture diagram, and Customization, plus a note to check `SKILL.md`'s "Configuration" line and `CLAUDE.md`'s architecture notes for the same drift. Found because README.md was, in fact, out of sync: missing `risk_tier`, `.clearfelt/audit.log`, the test suite, the eval set, and the sorted-output work above entirely, and its two worked examples displayed scores (41, 92, 55, 88) that no longer matched what `scripts/detect.mjs` actually returns for that exact text (56, 100, 83, 100) after this session's scoring changes. README, `SKILL.md`, and `CLAUDE.md` all updated to match current behavior.

### Known regression, disclosed rather than tuned away

- Raising `vocabulary_diversity_weight` as part of the ADR 0011 rebalance made `scripts/eval.mjs`'s existing AI-heavy misses score even further from their expected band (78 up to 83, 78 up to 83, 94 up to 99, 88 up to 93, 87 up to 91; pass rate stays 5/10). Type-token ratio correlates with document length, not AI-ness, so short single-paragraph AI samples (the same known weak spot from ADR 0010) get a larger undeserved bonus under the new weight. ### Fixed

- `loadConfig()` never parsed `clearfelt.config.md`'s "Category severity weights" section, and `computeScore` looked up weights under a `weight_<category>` key that was never populated. Every category silently scored at a 1.0 multiplier regardless of what the config file said, since the skill's original bootstrap. Both are fixed: the section is now parsed, and `computeScore` reads weights by category name directly. Anyone who had customized a category weight will see their score change to reflect the setting they actually configured.
- **Single-word lexicon matching was exact-literal-form only.** A rule for "leverage" never caught "leveraging"; "seamless" never caught "seamlessly"; "synergy" never caught "synergies." Found via dogfooding: a real test document scored 100/100 at every humanize intensity while still containing four unflagged, unmistakably AI-sounding words. `scripts/detect.mjs` gained `inflectionPattern()`, a heuristic (not real stemming) covering silent-e drop before `-ing`/`-ed`, the common `-s`/`-es`/`-ed`/`-ing`/`-ly` suffix set, and consonant+y pluralization (`synergy` becomes `synergies`). Applies only to single-word rules; multi-word phrases are unaffected. Scores will drop for any text that was previously under-flagged because of this gap, this is a correctness fix, not a new false-positive source.
- Added `synergy`, `synergistic`, `paradigm shift`, and `paradigm-shattering` to `rules/banned_words/puffery_lexicon.md` (`source: clearfelt-heuristic`), the two lexicon words the dogfooding test surfaced as missing entirely.

**Breaking:** `intensity`'s valid values changed from `conservative`/`aggressive` to `light_touch`/`balanced`/`full_rewrite`/`structural_rework`, called out explicitly per `docs/RELEASE.md`'s rule on config setting-name changes. Anyone who had `intensity: conservative` or `intensity: aggressive` set in `clearfelt.config.md` or `~/.clearfelt/settings.md` needs to update it to the new slug (`conservative` maps to `light_touch`, `aggressive` maps to `full_rewrite`).

- **Tiers redesigned so each one touches a genuinely larger scope, not just polishes harder.** Found via testing: `balanced`, `full_rewrite`, and `structural_rework` all scored identically on a real document because none of them were scoped to touch words tier-suppression had hidden from the scored report, only the same 4 flagged spans plus rhythm. `scripts/detect.mjs --mode scan <path>` is new: it returns every rule-dictionary occurrence with tier-suppression bypassed (tiering protects the *score* from single-legitimate-use false positives, it was never meant to protect what `/clearfelt humanize` is allowed to edit). `balanced` and above now use it. Result on the test document: `light_touch` (42) to `balanced` (99) is now a real, earned 57-point jump instead of a tie. `full_rewrite` and `structural_rework` still land close to `balanced` once there's nothing left to deduct for, that's an honest consequence of the remaining differentiator being fine statistical polish, not a bug. See `reference/humanize.md`'s "Choosing an intensity" for the full per-tier scope.
- **Two new scoring signals: paragraph-length variety and a wall-of-text penalty.** Every existing statistical signal (burstiness, vocabulary diversity, trigram repetition) operates on a flattened sentence/word stream and was completely blind to paragraph structure, found when a `structural_rework` pass that only changed paragraph boundaries moved the score by exactly zero. New `paragraphStructureScore()` (same coefficient-of-variation approach as burstiness, one level up, Markdown headers excluded from the count) and a flat `wall_of_text_penalty` for a long document crammed into a single paragraph. New `clearfelt.config.md` rows: `paragraph_variety_weight` (8), `wall_of_text_penalty` (15), `wall_of_text_sentence_threshold` (5).
- **Score breakdown surfaced in the actual output, not just the JSON.** `scripts/detect.mjs` was already computing and returning every component of the final score (rule-hit deduction, burstiness, vocabulary diversity, trigram repetition, paragraph variety, wall-of-text penalty) in its `breakdown` object, but `/clearfelt audit` and `/clearfelt humanize` never showed it, only the single final number. Two files landing on the same score looked like a bug with no way to tell why from the response alone. New "Score breakdown" table in both templates in `reference/output-format.md` (`/clearfelt audit` shows one; `/clearfelt humanize` shows a before/after pair), always shown, not just on request.
