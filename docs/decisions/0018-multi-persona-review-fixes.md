# ADR 0018: Fixes from a three-persona review (writing, engineering, pipeline design)

**Status:** Implemented
**Date:** 2026-08-13

## Context

A structured review of the whole repo from three different angles (prose/self-consistency, software engineering, agent-pipeline design) surfaced several concrete, fixable issues, none structural. This ADR records what was found and what changed, in one place, rather than scattering the rationale across commit messages.

## Findings and fixes

**The skill's own prose failed its own bar.** `SKILL.md`, `voice.md`, and `README.md` each scored below `human_score_threshold` (85) when audited with `scripts/detect.mjs`, driven by repeated phrasing across sections and files. Reworded the repetitive passages; all three now score 85+. Added an "audit the skill's own prose" step to `docs/RELEASE.md`'s checklist so this can't regress silently.

**`reference/audit.md` still described Root TTR as the scoring input** after `docs/decisions/0017` replaced it with MATTR. Fixed the formula table to match.

**`CLAUDE.md`'s em-dash rule contained a literal em-dash**, inside the grep pattern used to detect one, technically violating its own "anywhere, ever, including this file" wording. Rewritten to reference the Unicode codepoint (`grep -rnP "\x{2014}"`) instead of the character itself.

**`reference/write.md`'s length-tier word counts were hardcoded**, duplicated again in `reference/output-format.md`, with no row in `clearfelt.config.md`, violating this repo's own "one config file" rule. Added a `Write lengths` table to `clearfelt.config.md` (`short_min_words` through `long_min_words`); both reference files now cite it instead of hardcoding numbers.

**`SKILL.md`'s frontmatter carried a non-standard `version` field**, flagged by `scripts/lint.mjs`'s own frontmatter check. Removed it; the version is already tracked in `CHANGELOG.md`.

**`scripts/lib/config.mjs`'s `CONFIG_DEFAULTS` held stale, pre-`docs/decisions/0011` scoring weights** (`burstiness_weight: 10`, `vocabulary_diversity_weight: 5`, `repetition_weight: 5`, versus the shipped `12`/`140`/`27`). Because `loadConfig()` merges defaults under the shipped config, this was invisible as long as `clearfelt.config.md`'s rows stayed intact, but a user hand-editing that file (the whole point of it being plain Markdown) and dropping a row would have silently gotten the stale JS default instead of `scripts/lib/score.mjs`'s own correct inline fallback, since `??` only fires on `undefined` and `CONFIG_DEFAULTS` already supplied a wrong-but-defined value first. Corrected the three values and added the previously-missing keys (`deduction_cap`, `vocabulary_diversity_baseline`, `paragraph_variety_weight`, `wall_of_text_penalty`, `wall_of_text_sentence_threshold`). Added `scripts/lint.mjs`'s `checkConfigDefaultsDrift()`, which cross-diffs every `config.<key> ?? <literal>` fallback in `score.mjs` against both `CONFIG_DEFAULTS` and `clearfelt.config.md`'s shipped defaults, failing the build if any two disagree. `scripts/lint.mjs` also no longer hardcodes its own copy of `CONFIG_SECTIONS`, importing it from `scripts/lib/config.mjs` instead, the same category of bug this new check exists to prevent, found in the file meant to prevent it.

**`hook.mjs` had zero test coverage** despite parsing untrusted stdin JSON, doing its own path-containment check, and hand-rolling glob matching. Added `tests/hook.test.mjs` (12 tests: admin actions, malformed stdin, out-of-cwd rejection, ignore-glob matching, non-text extensions).

**`detect.mjs` and `hook.mjs` computed a file extension by hand** (`name.slice(name.lastIndexOf('.'))`), silently wrong for a dotless filename, when `node:path`'s `extname()` (already imported in both files) does this correctly. Swapped both call sites.

**Nothing validated the JSON shape `detect.mjs` and `check.mjs` print**, the boundary where a model reads that output over Bash with no schema between the two, unlike the input-side formats already documented in `schemas/`. Added `schemas/detect-report.schema.json` and `schemas/check-report.schema.json`, and `scripts/lint.mjs`'s `checkOutputShape()`, which runs both scripts against a real fixture and asserts every field the schemas mark required actually exists in the output.

**The eval corpus (16 fixtures) had a real, disclosed miss** (`ai-7.md` scored 77 against an expected 0-70 band) and was thin relative to the credibility `README.md` implicitly claims for it. Investigating the miss surfaced two genuine rule-dictionary gaps, not a threshold problem: "landscape" had no rule entry at all, and the "In today's ... world/landscape/era/environment" throat-clearing family only matched one exact literal string. Added the missing word and four regex variants. The same investigation, extended to a wider set of newly-added fixtures, found a second real gap in inspirational/personal-reflection register ("trust the process," "the best is yet to come," "here's to the next chapter"), also fixed with new rule entries rather than a loosened band. Grew the corpus from 16 to 28 fixtures, adding three new genre buckets (`marketing`, `technical`, `personal`) alongside the existing `support`, `executive`, and `sensitive`, and gave `scripts/eval.mjs` a per-bucket pass-rate breakdown so a strong aggregate number can't hide a weak genre. All 28 fixtures are now in-band. 28 is still short of a from-scratch benchmark corpus (see `docs/decisions/0012`'s and `0010`'s existing caveats on this); growing it further remains open, tracked the same way as any other rule-dictionary gap: dogfood, find a miss, fix the root cause, add the fixture.

**`CLAUDE.md`'s Architecture section moved to `docs/ARCHITECTURE.md`**, referenced from `CLAUDE.md` rather than inlined, at the user's explicit request during this session; the content and per-file rationale are unchanged.

**Unresolved-sourced rules counted against a user's score by default.** `camaraderie`, `palpable`, and `intricate` in `rules/banned_words/high_frequency_lexicon.md` carry an `unresolved-carnegie-mellon-pnas-2025` source, an honest disclosure that the citation couldn't be traced to a real paper, not a settled citation. Shipping them as scored defaults anyway contradicted README.md's "nothing asserted without a disclosed origin" claim. Added `rules.include_unresolved` to `clearfelt.config.md` (default `false`); `scripts/lib/rules.mjs`'s `loadRules()` now filters any `unresolved-*`-sourced entry, shared or `.local.md`, out of both the scored report and `/clearfelt rewrite`'s edit scope unless a project opts in. Narrowed `README.md`'s claim to disclose the exclusion rather than imply every rule is equally settled.

**A related bug surfaced while wiring up that new boolean setting**: `scripts/lib/config.mjs`'s `parseConfigTable` stored `true`/`false` cells from `clearfelt.config.md` as the literal strings `"true"`/`"false"`, not real booleans. Every strict `=== true` / `!== false` comparison downstream (`check.mjs`'s three hard-fail toggles) was silently wrong in at least one direction: `check.hard_fail_on_dropped_fact`/`_on_added_fact` could never actually trigger even when a project explicitly set them to `true`, and `check.hard_fail_on_locked_span_mismatch` could never actually be turned off. Fixed `parseConfigTable` to coerce `"true"`/`"false"` to real booleans, the same way it already coerces numeric strings to `Number`.

**The "qualitative signals" reasoning step had no eval coverage at all**, unlike every numeric part of the score. Added `tests/fixtures/qualitative/` (4 labeled fixtures, 2 ai/2 human, judged against `reference/audit.md`'s five signals: narrative idiosyncrasy, episodic grounding, cognitive friction, synonym cycling, admits real stakes) and `scripts/qualitative-eval.mjs`, which scores recorded judgment runs against the manifest and, once two or more runs exist, reports pairwise agreement between them. This script cannot produce a judgment itself, only score one already recorded (`tests/fixtures/qualitative/runs/*.json`, protocol in that directory's `README.md`), since the signals are explicitly a reasoning step this repo makes no API call to automate. Seeded two real runs to validate the harness: a live judgment (20/20 against the manifest) and an independent subagent judgment with no prior context (18/20), 90% pairwise agreement, the one disagreement landing exactly where `reference/audit.md`'s own text already flags synonym cycling as "the harder case." A small, honest first measurement, not a finished benchmark; growing the fixture set and running more independent passes is future work, tracked the same way as the eval corpus above.

## What this ADR does not cover

Nothing from the original review scope remains unaddressed; the qualitative-signals gap above was the last open item.
